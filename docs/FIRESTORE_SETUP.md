# Firestore セットアップガイド

## 概要

このアプリは、自分の Firebase(Firestore)に作品を保存して、複数の端末で同期できます。同期は任意で、設定しなくても全機能を使えます。

- 同期できるのは、**オーナー登録した端末**です。新ルール(`firestore.rules`)の Firebase では、最初に接続した端末が自動でオーナーになり、2 台目以降は、オーナー端末の「設定コード」を貼り付けて登録します(下記「オーナー鍵と設定コード」)。Firebase の設定値を知っているだけの端末は、データにアクセスできません。
- 旧ルール(認証済みなら全開放)のままの Firebase では、従来どおり、同じ設定値を入力した端末どうしで同期できます。**新ルールの適用は任意です。**適用しなくても同期は使えます。共有・共同編集(招待リンク)を使うときだけ、新ルールが必要です。
- 新ルールの適用で、既存のデータは消えません。ただし、適用した時点で、オーナー登録のない端末は同期できなくなります(下記)。

## データ構造

権限とデータ配置の正本は [SHARING_RULES.md](SHARING_RULES.md) です。要約は次のとおりです。

```
projects / chapters / scenes / characters / plots / worldbuilding   従来コレクション(任意ネスト含む)。オーナーのみ
owners/{uid}                      オーナー端末の登録 {key}
_config/ownerKey                  オーナー鍵 {key}(クライアントは読めない)
shared/{projectId}                共有メタ {visibility, name, ...}
shared/{projectId}/secrets/{role}      招待の秘密(クライアントは読めない)
shared/{projectId}/members/{uid}       参加者
shared/{projectId}/presence/{uid}      在席情報・カーソル
shared/{projectId}/{type}/{id}[/...]   共有中の作品の本文・設定など(type は従来の 6 コレクション)
```

- 従来の 6 コレクションは、作品の種類ごとの最上位コレクションで、各文書に `id`・`projectId`・`updatedAt` などを持ちます。シーン本文の共同編集用の更新ログ(CRDT)は、シーン文書の下位コレクションに置かれます。
- ユーザー別の分離はなく、オーナー登録した端末は全データにアクセスできます。
- 共有中の作品は、`projects/{projectId}` に「ポインタ」だけを残し、子要素は `shared/{projectId}/...` に置きます(招待したゲストはここだけを読み書きできます)。

## セキュリティルールの設定

Firebase Consoleで以下の手順を実行してください:

1. **Firebase Console** (https://console.firebase.google.com/) を開く
2. プロジェクトを選択
3. 左メニューから **Firestore Database** を選択
4. **ルール** タブをクリック
5. リポジトリの [`firestore.rules`](../firestore.rules) の内容を全文コピー＆ペースト。アプリの 設定 → 「Firebase ルール」カードにも同じ全文とコピーボタンがあります(ビルド時に `firestore.rules` を取り込んでいます)
6. **公開** をクリック

事前に Authentication で「匿名」プロバイダを有効にしてください。

ルールの全文は `firestore.rules` が唯一の正本です(この文書には複製しません)。

## オーナー鍵と設定コード

認証は匿名認証のままです。新ルールでは、従来の 6 コレクション(`projects` / `chapters` / `scenes` / `characters` / `plots` / `worldbuilding`)に、**オーナー登録した端末**だけがアクセスできます。

- **最初の端末**: 新ルールの公開後にアプリを開くと、自動で `_config/ownerKey`(オーナー鍵)と `owners/{uid}` が作られ、その端末がオーナーになります。操作は不要です。
- **2 台目以降の端末**: そのままでは従来コレクションにアクセスできず、同期は止まって「このFirebaseは新しいルールで保護されています。オーナー端末の設定コードを貼り付けてください」と表示されます。オーナー端末の 設定 → 「設定コード」カードで表示/コピーした設定コードを、新しい端末の初回画面の一括貼り付け欄、または 設定 → 「設定コードの入力」に貼り付けてください(Firebase Console の設定値の代わりになります)。貼り付けると自動でオーナー登録され、同期が始まります。
- **設定コード**は Firebase の設定とオーナー鍵を 1 つにした文字列(`storift1:` で始まる)です。**このコードを持つ人は全データにアクセスできます。** 共有には使わず、自分の別端末にだけ貼ってください。
- 匿名認証の ID はブラウザのデータ消去などで変わります。その場合は、新しい端末として設定コードを貼り直してください。
- **先着の注意**: オーナー鍵がまだ無い間は、最初に登録した端末がオーナーになります。新ルールを公開したら、速やかに自分の端末でアプリを開いてください。
- 鍵の変更(ローテーション)や端末の失効は、Firebase Console で `_config/ownerKey` の `key` の更新、`owners/{uid}` の削除で行います。登録済みの端末は鍵を変えても影響を受けません。

## 旧ルールとの互換

従来のルール(認証済みなら 6 コレクションを全開放)のままの Firebase に新しいアプリが接続しても、**従来どおり同期できます**。この場合、共有機能だけが使えません(設定 → 「Firebase ルール」カードに「旧ルール」と表示されます)。

アプリは起動後に裏で次のように判定します(操作は不要)。

1. `owners/{自分のuid}` が読めて存在する: 新ルール・オーナー
2. 読めるが存在しない: 新ルールで未登録。保存済みの設定コードがあれば登録、無ければ最初の端末として登録を試み、拒否されたら「設定コードが必要」
3. 読み取りが拒否される: 旧ルールの可能性。従来コレクションが読めれば旧ルール、読めなければ「設定コードが必要」
4. 通信エラー等: 判定せず、前回の結果を使う(オフライン起動も同様)

判定のたびに `owners/{uid}` の読み取りが 1 回(旧ルールではさらに 1 回)発生します。ルールの `exists()` / `get()` も読み取りとして課金されます([SHARING_RULES.md](SHARING_RULES.md) 参照)。

設定画面の「接続診断」で、Firestore への到達・匿名認証・ルールの版・オーナー登録を確認できます。

## 招待リンクでの共有(ホストとゲスト)

共有を開始したプロジェクトは、共有ダイアログで権限(閲覧/編集)を選んで「招待リンクを作成」し、相手に渡します。相手(ゲスト)はリンクを開く(デスクトップ版ではホームの「共有リンクから参加」に貼り付ける)と参加できます。ゲストは自分の Firebase 設定を持っていなくても共有プロジェクトを開けます。

- 招待リンクには**ホストの Firebase 設定**・プロジェクト ID・権限が入ります。トークン方式の秘密はリンクに入り、パスワード方式の秘密はリンクに入りません(パスワードは別途伝えてください)。**リンクを知っている人は誰でも参加できます。** 漏れたら共有ダイアログで秘密を再生成してください。再生成後は新しいリンクが必要で、参加済みのメンバーは自動では失効しません(必要ならメンバーを削除)。
- ゲストは**ホストの Firebase に匿名認証で接続**します。ホスト側の Firebase で次を確認してください。
  - Authentication で「匿名」プロバイダが有効(通常の同期と同じ)。
  - 承認済みドメインに、**ゲストが使うアプリのドメイン**が入っていること(Authentication → 設定 → 承認済みドメイン。公開版なら `app.storift.shiki-01.com` など)。ゲストが開くアプリのドメインが未登録だと、ゲストのサインインが拒否されます。自分の環境で配信している場合は、そのドメインです。
- **新ルール(共有機能に必要)の適用が必須です。** 旧ルール(認証済みなら全開放)のままの Firebase では、ゲストは参加できません(参加が拒否され、「新しいルールが適用されていない可能性があります」と案内されます)。また、自分の Firebase が旧ルールのまま、同じ Firebase の招待リンクを開いた場合も、新ルールが未適用と案内して止まります。
- ゲストのデータは、ゲスト自身の Firebase には保存・同期されません(ホストの Firebase とゲストの端末だけ)。ゲストは共有から退出すると、端末のコピーを「ローカル専用で残す」か「削除する」かを選べます。
- ホストが自分の Firebase の端末(オーナー端末)で招待リンクを開いても、参加は不要です(通常の同期で開けます)。
- ゲスト 1 人あたりの接続は、ホストの Firebase の読み取り・書き込み(無料枠)を消費します。

詳しい仕組みは [SHARING_RULES.md](SHARING_RULES.md) の「招待リンク・ゲスト接続」を参照してください。

## 動作確認

1. 1 台目(ChromeなどのFirebase設定を入力した端末)で「保存して開始」をクリック(新ルールなら、この端末がオーナーになる)
2. 設定 →「設定コード」で表示したコードをコピーする
3. 2 台目(別の端末やブラウザ)で、初回画面の一括貼り付け欄に設定コードを貼り付ける(旧ルールのままなら、同じ Firebase 設定の 6 項目で足りる)
4. 片方でプロジェクトを作成し、もう片方に表示されることを確認

## トラブルシューティング

### データが同期されない場合

1. **ブラウザのDevToolsを開く** (F12)
2. **Console** タブを確認してエラーメッセージを探す
3. よくあるエラー:
   - `Missing or insufficient permissions` → Firestoreルールが正しく設定されていない。新ルールの場合は、この端末がオーナー未登録の可能性があります(設定コードを貼り付けてください)。設定の「接続診断」で確認できます
   - `Auth not initialized` → ページをリロードしてみる

## セキュリティについて

新ルールでは、オーナー鍵(設定コード)を持つ端末だけが従来コレクションにアクセスできます。Firebase の設定値を知っているだけの第三者は、オーナー登録済みでなければデータを読み書きできません(ただし、鍵が未作成の間は先着でオーナーになれる点に注意してください)。

オーナー同士は互いを区別せず、オーナーは全データにアクセスできます。ユーザーごとのデータ分離が必要な場合は、メール/パスワード認証など別の仕組みが必要です。

## 開発者向け情報

### リアルタイム同期の仕組み

1. 開いている作品だけを `onSnapshot()` で監視する(`startCurrentProjectSync`)。一覧用の作品の監視はグローバルに 1 本
2. それ以外のデータは、タブ表示・オンライン復帰・定期の差分取得(`updatedAt` の条件付き)で取り込む
3. 取得した内容はローカルの IndexedDB に反映し、UI が自動で再描画される

読み取りの回数を抑える工夫の詳細は [SYNC_OPTIMIZATION.md](SYNC_OPTIMIZATION.md) を参照してください。

### オフライン対応

Firestoreの `persistentLocalCache` により、オフライン時も以下が可能:

- ローカルキャッシュからの読み取り
- 変更の一時保存（オンライン復帰時に自動同期）
- 競合の自動解決
